# ชุดย้าย Dashboard ไป Google Apps Script

จัดเตรียมจากเว็บปัจจุบัน วันที่ 5 ตุลาคม 2569 ยังไม่ได้ Deploy หรือทดสอบบนบัญชี Google จริง

## วิธีติดตั้ง
1. เปิด Google Sheets ฐานข้อมูล https://docs.google.com/spreadsheets/d/1RQDU83exQhNpVYjp9JyD5UdocA6JB6GpJeXA-Qe8Pr4/edit
2. เลือกส่วนขยาย → Apps Script สร้างโครงการสำหรับ Dashboard แยกจากสคริปต์นำเข้าข้อมูลเดิม เพื่อไม่ให้ doGet ชนกัน
3. สร้างไฟล์สคริปต์ `Code` และ `Config` แล้ววางเนื้อหาจาก Code.gs และ Config.gs
4. สร้างไฟล์ HTML ตามชื่อเดิมทั้ง 8 ไฟล์: Index, Styles, Dashboard, DataModel, RiskView, GeoJSON, BkkGeoJSON, RegionsGeoJSON คัดลอกเนื้อหาให้ครบ
5. Settings → เปิด Show appsscript.json manifest file แล้ววางเนื้อหา appsscript.json ใช้เขตเวลา Asia/Bangkok และสิทธิ์อ่าน Spreadsheet เท่านั้น
6. เรียก getDashboardData จากตัวแก้ไขครั้งแรกและอนุญาตให้อ่าน Sheets ด้วยบัญชีที่มีสิทธิ์ในไฟล์
7. Deploy → New deployment → Web app ตั้ง Execute as เป็นบัญชีผู้เผยแพร่ เลือกสิทธิ์ผู้เข้าชมให้ตรงกลุ่มใช้งาน เริ่มทดสอบเฉพาะผู้มีสิทธิ์ก่อน หากเปิดสาธารณะ ผู้เข้าชมจะเห็นข้อมูล Dashboard ที่สคริปต์อ่านได้
8. เปิด URL ลงท้าย /exec ทดสอบตามรายการด้านล่าง แล้วจึงใช้แทน Cloudflare URL คอมพิวเตอร์เดิมไม่ต้องเปิดเซิร์ฟเวอร์ค้างไว้
9. เมื่อแก้โค้ดหลังเผยแพร่ ให้ Deploy → Manage deployments → Edit → New version

## ฐานข้อมูล
ใช้ Sheets เดิม ไม่ต้องนำเข้า Excel ซ้ำ ไม่แก้หรือเขียนทับข้อมูลต้นทาง

| ชื่อแท็บ (ตรงตัวพิมพ์) | ใช้สำหรับ | ผลลัพธ์ให้หน้าเว็บ |
|---|---|---|
| Disaster_DB | รายงาน ปภ. ทุกวัน | disasters |
| Vulnerable_group | ประชากรเปราะบาง | vulnerable |
| thai_water_DB | สถานีทั่วประเทศ | stations |
| BKK_water_DB | สถานี กทม. | bkkStations |
| shelter_DB | ศูนย์พักพิง | shelters |
| flood_risk (optional) | ความเสี่ยงรายจังหวัด จาก pipeline เตรียมรับน้ำท่วม | floodRisk |
| flood_wl_critical (optional) | สถานีน้ำระดับ 4-5 พร้อมพิกัด | floodCritical |

schema.json และ Config.gs ระบุหัวคอลัมน์ที่จำเป็น คอลัมน์ตัวเลข และคอลัมน์วันที่ตาม backend ปัจจุบัน หัวตารางอยู่แถวแรก ไม่รวมเซลล์ในตารางข้อมูล แถวว่างถูกข้าม ค่าว่างเป็น null ไม่แปลงเป็นศูนย์ ตัวเลขรับคอมมาได้ วันที่รับ Date ของ Sheets, ISO และวัน/เดือน/ปี พ.ศ. หรือ ค.ศ. โดยส่งกลับเป็นข้อความเวลาไทยเพื่อใช้กับ google.script.run

อ่านทั้ง 7 ชีตเมื่อเปิดหน้า (5 ชีตหลัก + 2 ชีต optional ของแท็บ "เตรียมรับน้ำท่วม" ซึ่งถ้าอ่านไม่ได้จะไม่กระทบแท็บอื่น) ไม่ใช้ข้อมูล snapshot ผลการอ่านแต่ละชีตถูกแคชด้วย CacheService 5 นาที (แบ่งก้อนละ 30,000 ตัวอักษรเพราะข้อจำกัด 100 KB ต่อค่า) ข้อมูลที่แก้ในชีตอาจปรากฏช้าสุด 5 นาที ชีตที่อ่านผิดพลาดจะไม่ถูกแคชและอ่านใหม่ทุกครั้ง หากแคชใช้ไม่ได้จะอ่านชีตตรง เวลา "อ่านล่าสุด" ท้ายหน้าคือเวลาที่อ่านชีตจริง ไม่ใช่เวลาเปิดหน้า ปุ่มลองใหม่อ่านเฉพาะชีตที่เลือก เมื่อชีตหนึ่งผิดพลาด ส่วนอื่นยังส่งกลับได้ หากเปิดไฟล์ฐานข้อมูลไม่ได้จะแสดงข้อผิดพลาดทั้งหน้า

ขอบเขตจังหวัด เขต กทม. และเขตสุขภาพรวมอยู่ใน HTML ไม่ต้องมีเซิร์ฟเวอร์ไฟล์ JSON ส่วน Leaflet/Chart.js/Heatmap ยังโหลดผ่าน HTTPS จึงต้องใช้อินเทอร์เน็ต

## ตรวจรับหลัง Deploy
- sourceStatus ของ 5 ชีตหลักเป็น ok (ชีต flood_risk และ flood_wl_critical เป็น ok เมื่อ pipeline เขียนแล้ว); เทียบจำนวนแถวกับชีตต้นทาง
- เลือกวันรายงานล่าสุดและย้อนหลังได้; ตัวเลข ปภ. ตรงกับวันและจังหวัดที่เลือก
- รายละเอียดสถานีแสดงเฉพาะวันล่าสุด; ตรวจเวลาไทยไม่คลาด 7 ชั่วโมง
- แท็บ กทม. แสดง 50 เขต หมุดศูนย์สีตามสถานะ ไม่มีการรวมกลุ่ม
- ทดสอบกรอง ตาราง เลเยอร์ ดาวน์โหลด CSV และมือถือทั้งสองแท็บ
- ตารางสรุปสถานีรายเขตไม่มีคอลัมน์เก่า >24ชม.
- แก้ข้อมูลตัวอย่างในสำเนา Sheets แล้วโหลดใหม่ ตรวจว่าตัวเลขเปลี่ยน
- ทดสอบแท็บหาย/หัวคอลัมน์ผิดในสำเนา และปุ่มลองใหม่หลังแก้กลับ
- ทดสอบด้วยบัญชีผู้เข้าชมจริง และวัดเวลาโหลดเมื่อใช้หลายคนก่อนเปิดวงกว้าง

## ข้อสังเกตที่ยังต้องตกลง
บัตร “เขตที่ไม่มีศูนย์พักพิง” ในโค้ดปัจจุบันนับรวมเขตที่ไม่พบศูนย์ในข้อมูล และเขตที่ทุกศูนย์เต็ม ชื่อบัตรยังไม่ตรงความหมายทั้งหมด ตัวเลข 15 จากภาพเก่าไม่ใช่หลักฐานว่า 15 เขตไม่มีศูนย์จริง ควรแยกสองตัวชี้วัดก่อนใช้สรุปเชิงนโยบาย

## สร้างชุดใหม่จากเว็บ
รัน `python outputs/flood_apps_script_ready/build.py` จากโฟลเดอร์ SAT เมื่อแก้หน้าเว็บ คำสั่งจะสร้าง HTML และ Config ใหม่ โดยเก็บ Code.gs และคู่มือนี้ไว้ ชุดเก่า outputs/flood_apps_script ไม่ได้ถูกเขียนทับ อย่านำ build_gas รุ่นเก่ามารันกับชุดนี้
